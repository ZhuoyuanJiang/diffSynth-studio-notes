# Our Custom Implementation vs Upstream's Official Method

## TL;DR - The Difference

**Our approach:** Wrote specialized code for RenderMe360
**Upstream approach:** Use generic tools with configuration parameters

**Good news:** Our metadata and data files are 100% compatible! Just need to adapt column names.

### Layer 2: Metadata CSV (MINOR ADAPTATION NEEDED)

#### Our Custom Approach (notes-and-scripts)
**File:** `metadata_single2multi.csv`
```csv
subject_id,clip_id,video_path,audio_path
0001,clip_000,0001/clip_000,0001/clip_000/audio.wav
0001,clip_001,0001/clip_001,0001/clip_001/audio.wav
```

**Generated by:** `scripts/generate_metadata_single2multi.py`

**Logic:**
- Scans `/ssd2/zhuoyuan/renderme360_4cam/`
- Stride = 150 frames (0% overlap)
- Boundary check: `max_start = total_frames - 151`
- Validates all 4 cameras exist

#### Upstream's UnifiedDataset Approach
**File:** `metadata_upstream.csv` (needs to create)
```csv
video,input_audio
0001/clip_000/video_4cam.mp4,0001/clip_000/audio.wav
0001/clip_001/video_4cam.mp4,0001/clip_001/audio.wav
```

**Key difference:**
- Column names: `video,input_audio` instead of `subject_id,clip_id,video_path,audio_path`
- Full paths with filenames instead of directory paths

**Can we reuse our generation script?** ✅ YES! Just modify output format:

```python
# OLD (our custom):
csv_data.append({
    'subject_id': subject_id,
    'clip_id': clip_id,
    'video_path': f'{subject_id}/{clip_id}',
    'audio_path': f'{subject_id}/{clip_id}/audio.wav'
})

# NEW (for UnifiedDataset):
csv_data.append({
    'video': f'{subject_id}/{clip_id}/video_4cam.mp4',
    'input_audio': f'{subject_id}/{clip_id}/audio.wav'
})
```

**Conclusion:** ✅ Script logic is the same, just change output columns

**File:** `diffsynth/trainers/unified_dataset.py` (already exists in repo)

**What it does:**


**Conclusion:** Use upstream's train.py with correct parameters instead of our custom train_s2v.py

## What Can We Reuse?

### ✅ Can Reuse 100%
1. **Data files** - Already prepared, don't touch
2. **Metadata generation logic** - Same scanning/boundary checking, just change output format
3. **Data validation scripts** - Validate actual files, independent of dataset class
4. **Frame sampling math** - `(k*30+8)//16` is still correct
5. **Audio loading logic** - Same approach, just in different place

### ❌ Cannot Reuse (Replaced by Upstream)
1. **RenderMe360S2VDataset class** - Use UnifiedDataset instead
2. **train_s2v.py** - Use upstream's train.py instead
3. **Custom collate function** - UnifiedDataset handles this

### 🔄 Need Adaptation
1. **CSV format** - Change columns from `subject_id,clip_id,video_path,audio_path` to `video,input_audio`
2. **Training script call** - Use different parameters with train.py

## Why Upstream's Approach is Better

1. **Less code to maintain** - No custom dataset class
2. **Standard interface** - Uses same train.py as all other models
3. **Flexible** - Just change CSV columns to use different data
4. **Official support** - If it breaks, upstream will fix it
5. **Same functionality** - Does everything our custom code did
